# Feedback Loop Product Brief

## Problem

대학생의 과제 기준과 교수님 피드백은 강의계획서, LMS 공지, 팀플 대화,
채점기준표, 제출 후 코멘트에 흩어진다. 학생은 제출 전에 무엇을 확인해야
하는지와 과거에 반복해서 지적받은 내용을 다시 찾기 어렵다.

## Core value

제출물을 대신 작성하거나 점수를 예측하지 않고, 사용자가 제공한 수업 자료와
피드백을 근거로 제출 전 확인 항목을 만들고 반복되는 개선 포인트를 다음
과제에 연결한다.

## MVP scope

- 과제별 강의계획서·공지·팀플 공지·채점기준·피드백 업로드
- 자료를 바탕으로 한 과제 요구사항 정리
- 초안의 필수 조건·채점기준·반복 피드백 검토
- 검토 결과에 근거 자료와 관련 문단 표시
- 피드백의 확인·반영·개선 상태 기록
- 여러 과제에서 발견된 개인 인사이트의 사용자 승인·수정·숨김

## Product boundaries

- `frontend/`는 PC 웹 화면, 상호작용, 검토 결과 표시를 담당한다.
- `backend/`는 API, 문서 처리·AI 분석, 파일·데이터 저장을 담당한다.
- 팀 전체에 대한 피드백과 개인 피드백은 별도 데이터로 취급한다.
- 개인 인사이트는 근거와 함께 표시하며, 사용자가 확정하거나 수정할 수 있다.
- 실제 점수·교수님의 의도·학생의 성격을 단정하지 않는다.

## Primary flow

```text
과제 생성
→ 수업 자료 등록
→ 초안 업로드
→ 제출물 검토
→ 피드백 반영 상태 기록
→ 누적 인사이트 승인·수정
→ 다음 과제 검토에 재사용
```

## Out of scope for the first implementation

- 학교 LMS 자동 로그인·무단 크롤링
- 실제 성적 예측
- 교수자용 학급 분석 대시보드
- 팀원의 성실도 또는 인성 자동 판정
