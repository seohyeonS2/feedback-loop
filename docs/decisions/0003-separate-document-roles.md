# 0003. 과제 기준·초안·피드백 역할 분리

## Context

초기 화면은 모든 문서 유형을 과제 기준 자료의 단일 선택기에 노출했다. 이
구조에서는 제출 초안과 교수님 피드백이 수업 자료처럼 보이고, 피드백 문서가
검토 컨텍스트와 피드백 기록에 중복 전달될 수 있었다.

## Decision

- 과제 기준 자료는 강의계획서, 과제 공지, 채점기준으로 제한한다.
- 팀플 공지는 사용자가 과제 유형을 팀플로 선택했을 때만 과제 기준 자료에
  노출한다. 과제 유형이 없는 기존 데이터는 개인 과제로 간주한다.
- 제출 초안과 교수님 피드백은 각 단계의 전용 업로더에서 받는다.
- 검토 요청의 `contextDocuments`에는 과제 기준 자료만 넣는다.
- 원본 `feedbackRecords`에는 현재 과제의 피드백만 넣는다. 다른 과제에서
  재사용하는 내용은 사용자가 승인하거나 수정한 개인 인사이트로 제한한다.

## Consequences

문서의 역할이 화면과 API 입력에서 일치하며 같은 피드백이 중복 근거로 쓰이지
않는다. 새 과제를 만들 때 개인 과제와 팀플 과제를 선택해야 하며, 기존 백업은
필드가 없어도 개인 과제로 계속 열린다.
